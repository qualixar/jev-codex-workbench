# Qualixar Jev Codex Workbench 1.1.3

Readiness: jev_auto_status for the current workspace. When enrolled, do NOT ask for a
new terminal grant per task or after a code edit. The standing policy already authorizes
eligible data and recipes. Never create, renew, expand or disable that policy yourself.
For an unenrolled workspace only, retain the legacy 1.1.2 grant path or ask the owner
to run the one-time enrollment helper. Normal Codex work does not depend on enrollment.

## Daily operation
1. Use the prompt-time shortlist already provided. Do not repeatedly load catalogs.
2. For a known case, call jev_evaluate with case_id, workspace_path and minimized state.
   Responses are compact. Use jev_recall only for the evidence genuinely needed.
3. For long text not already handled by the output hook, jev_reduce accepts an explicit
   narrow goal. Omitted blocks remain exactly recoverable; errors and uncertainties stay.
4. Keep ordinary exact search, arithmetic, compilers, mandatory tests and mandatory rules
   in deterministic code. Do not ask Jev to decide which security rules to obey.
5. Use the bundled jev-auto-browser skill for repeated mechanical browser steps through
   the user's existing Computer Use tab. Do not open a second browser driver.
6. SLM remains the canonical memory source. Do not modify its stores, configs, hooks,
   profiles, temporal constraints, abstention signals or outcome tracking. Its MCP results
   are not generically rewritten. Pass selected public evidence to Jev only when useful.
7. Subagents share the workspace service and budget. Use small task-specific handoffs.
   Their narrow goals must be supplied explicitly when the host does not provide a usable
   session goal. They must never mint their own grants or duplicate full parent receipts.
8. A decision-provider timeout means continue ordinary Codex reasoning for that step.
   Do not retry the same failed call indefinitely and do not silently switch processors.

## Claims and limits
Fixtures are not inference. Local MLX is a pretrained optional route, not a trained-on-your-
repository model. MLX rejects evidence that would be truncated. A successful decision is
not tool permission. Existing native approvals remain. Character reductions are not token
or subscription-quota savings. Use the matched-run report for those claims.
